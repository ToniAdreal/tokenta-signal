A Credential Stealer Hid Inside Microsoft's Official Package — It Ran on Install

The sharpest trick in a supply-chain attack is not hiding deep — it is shipping from the official account. Once the certificates are gone, the signature itself becomes the disguise.

WHAT HAPPENEDWhat Happened

At 20:35 UTC on November 17, 2026, a malicious version of agent-framework, 1.26.1, was uploaded to PyPI. Thirty-three minutes later, 1.26.2 followed. Around 21:30, both versions were taken down. The whole window lasted about an hour; the package draws roughly 41,000 downloads a week.

The malicious code hid in a .pth file. Python executes the import lines in a .pth file on every startup, whether or not the user imports agent-framework. Once running, the stealer swept environment variables, credential files, and other processes' environments, and went after Azure managed identity tokens plus OIDC tokens for Azure DevOps and GitHub Actions. What it stole was compressed into a single JSON document and sent to a webhook.site address controlled by the attackers.

Wiz's analysis points to a more troubling source: the attackers appear to have stolen client certificates and private keys from Microsoft's ESRP release pipeline. ESRP is the internal Microsoft service used to sign and publish this package. With the certificates gone, the malicious versions came from Microsoft's official publishing account and looked indistinguishable from a normal update. The attackers' tooling calls itself Cairn, an open-source AI penetration-testing framework.

WHAT TO WATCHVersion Two Was Built to Beat the Diff

Version 1.26.2 was plainly designed to evade comparison. Its package init file is byte-for-byte identical to clean 1.26.0, with the malicious code moved into a new module, af_runtime_diag.py. Anyone diffing against the first version would conclude the second was clean.

Both versions kept their dependency on the legitimate agent-framework-core 1.26.0, so the framework kept working normally while the stealer ran in the background. Users felt nothing — the hardest part of supply-chain poisoning to defend against.

WHY IT MATTERSThe Signature Itself Became the Disguise

Eight security firms spotted the poisoning almost simultaneously — Wiz, Socket, StepSecurity, Endor Labs, and OX Security all published analyses. PyPI quarantined the packages fast, but anyone who installed them already had them.

This is the second Microsoft-related PyPI package compromised this year. The official advice is blunt: pin 1.26.0, rebuild from a clean environment, and rotate every credential that may have been exposed.

THE SHIFTWhat Changed

FROM BLOCKING BAD PACKAGES TO GUARDING THE PIPELINE
From blocking bad packages to guarding the pipeline
This poisoning used no fake account and no phishing link — the malicious versions came straight from Microsoft's official publishing account. The line of defense has to move from the package itself to the pipeline that issues its signatures.
FROM RUN ON IMPORT TO RUN ON STARTUP
From run on import to run on startup
The .pth file runs on every Python startup — installed means running, no import needed. The traditional check-after-install mindset is a step behind a hook like this.

SIGNAL JUDGMENT — ANALYSISA Credential Stealer Hid in Microsoft's Official Package — It Ran on Install

The sharpest trick in a supply-chain attack is not hiding deep — it is shipping from the official account. Once the certificates are gone, the signature itself becomes the disguise. Tokenta Signal's judgment: defending against poisoning, in the end, means defending the release pipeline itself.

WHAT REMAINS UNCERTAINWhat Remains Uncertain

How the attackers obtained publishing access has not been established; this piece reports only Wiz's analysis. The scale of victims is undetermined; Wiz saw only the 50 requests retained on the public webhook. This does not constitute investment advice.

EVIDENCEEvidence

Wiz disclosed that malicious versions 1.26.1 and 1.26.2 of Microsoft's agent-framework were uploaded to PyPI on November 17; the .pth file runs on every Python startup, stealing Azure and CI credentials.
