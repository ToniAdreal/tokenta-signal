700 个内网能力，一次接进企业 AI 助手

Interact Software 在 10 月 26 日发布 Interact MCP，一个模型上下文协议服务器，把内网已有的 700 项能力开放给获得授权的 AI 助手，覆盖 26 个内网领域，兼容 Claude、ChatGPT、Microsoft 365 Copilot 与 Gemini Enterprise。

WHAT HAPPENED发生了什么

Interact MCP 的定位是一个模型上下文协议服务器：把内网中已有的 700 项能力，开放给获得授权的 AI 助手。覆盖 26 个内网领域，从内容与通讯，到社区与分析。员工用各自已有的权限操作，助手不获得超出员工本人的权限。

使用场景按角色分开：员工可以按来源链接查找政策；通讯团队可以更新页面；平台负责人可以比较不同群体的采用情况。同一套能力，在不同角色手里变成不同的工作流。

THE PERMISSIONSMCP 的卖点，是权限不变

企业 AI 推广最常见的卡点不是模型能力，而是权限：助手能看到什么、能改什么。Interact MCP 的设计把权限锚定在员工本人，助手继承员工已有的权限，不额外开门。

这个设计把安全责任交回给企业已有的权限体系。助手不是一个新的特权账户，而是一个沿着现有权限走路的工具，审计与回收都沿用原有机制。

THE NUMBER700 这个数字，需要拆开读

700 项能力不是新功能，而是 Cue 与 Conductor 两个产品已有的能力经协议开放。数字的意义不在新增，而在可达：原来只能在内网界面里点的功能，现在可以在助手对话里调用。

对买家而言，真正要验证的是覆盖度：26 个领域里，自己的高频场景是否在列，助手调用的成功率如何。公告给出了总量，没有给出分领域的可用清单。

THE TWO-WAY LINK连接是双向的

公告的另一半常被忽略：Conductor 也可以接入支持 MCP 的外部系统，包括 Workday 与 SAP。内网与业务系统的连接从单向变成双向，助手可以在内网里调用外部系统的数据。

双向连接的价值与风险成对出现：工作流更完整，权限边界也更复杂。企业在开通前需要确认，外部系统的权限同样沿用员工本人的授权范围。

SIGNAL JUDGMENT助手的能力，取决于它能合法碰到什么

Interact MCP 的发布把企业 AI 的竞争点说得很清楚：模型可以通用，数据与权限不能通用。Tokenta Signal 的判断不变：企业 AI 的下一道门槛不在模型参数，而在权限体系能否被助手安全地继承。

WHAT REMAINS UNCERTAIN还有什么不确定

本篇的边界：全部功能描述来自 Interact 官方公告，尚未经独立客户验证；700 项能力为平台已有能力经 MCP 协议开放的数量，不是新增功能；各助手实际可用操作取决于配置与权限。本文不构成任何投资建议。
